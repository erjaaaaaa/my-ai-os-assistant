# Rules digest — what is still live in `lessons-learned.md` and not yet in a governing file

Drafted 2026-11-01 from `lessons-learned.md` (131 entries; per-entry disposition in `lessons-disposition.tsv`). Only DISTILL rules are here. Sweeps now run every 4 hours (00:59, 04:59, 08:59, 12:59, 16:59, 20:59 UTC), so "previous slot" means the previous 4-hour slot. Each rule cites its source as (date — short title). Placement is not decided here.

## [sweep] — inbox labelling, Step 0/1, cloud run

D01 [sweep] On a permission-layer refusal of a write ("Blocked by classifier", "Out-of-Place Publication", "Irreversible Local Destruction"): stop at that step, do not retry inside the run, and never reach the same outcome through another tool or interpreter. A less destructive act that satisfies the instruction is allowed (local ledger: clear the duplicate value, keep the row, annotate). It is not an outage and blocks no watermark. (2026-09-08 — permission-layer refusal; 2026-09-30 — local-file refusal)
D02 [sweep] When a carve-out write is refused, stop the remaining items of that same class for the run and list them as owed; do not start a second half-swapped thread. (2026-09-14 — classifier refusal mid-swap)
D03 [sweep] If a refusal leaves an object in a contradictory state (e.g. `Paid` + `Needs-Payment`), report it as the FIRST item of the final message, with the exact remaining calls and the one word that finishes it; never file it under Anomalies. (2026-09-14 — half-finished carve-out)
D04 [sweep] A classifier refusal is first-attempt and usually transient: state the failure as provisional ("commits unpushed and recoverable"), take exactly one more attempt only if Eriks or the stop hook asks, then correct the run log in place. (2026-09-21 and 2026-10-09 — CORRECTION entries)
D05 [sweep] Push with plain `git push origin main`, never `-u` (Step 5 §3 beats generic environment git guidance). Never route a refused push through the GitHub MCP. Before ending a refused-push run, write the verbatim ledger rows and watermark values into the run log and commit. (2026-10-08 — git push -u; 2026-09-21 — local push refusal)
D06 [sweep] At Step 0 of a cloud run, after the pull, compare the newest run-log entry and commit with the previous scheduled slot. If a slot has neither, treat that run's external writes as unrecorded: search the four archive-class labels for threads absent from their ledger and backfill before doing this run's own work. (2026-09-22 — lost-ledger-row failure)
D07 [sweep] Skip test: skip a thread if any message carries one of the thirteen labels OR `Paid` (a half-swapped carve-out-5 thread has `Paid` and none of the thirteen). Read labels from `get_thread`; a `search_threads` preview only decides which threads to look at. (2026-09-22 — mid-carve-out-5; 2026-09-17 — truncated message list)
D08 [sweep] After labelling, the sum of per-label `threadsTotal` deltas must equal the number of `label_thread` calls; any label showing +0 means that thread was already in the class. (2026-09-17 — already-labelled skip check)
D09 [sweep] When a thread is classified without its full body (oversized), the run log names the thread, says the body was not read, and states what carried the decision; never report it as a full read. (2026-09-20 — oversized threads)
D10 [sweep] Before classifying a sender earlier runs split across classes, grep the ledgers (sender column) for precedent, name the split in the brief's Anomalies, and classify on content. (2026-09-20 — same sender under three classes)
D11 [sweep] Receipts: before writing N rows for N messages in a thread, compare invoice numbers. Same invoice and same transaction: one row at the final amount, superseded messageId and figure in `notes`. Different transactions: N rows. Invariant either way: at least one verified row per archived thread. (2026-09-20 — corrected re-send)
D12 [sweep] Newsletters and Promotions: one row per messageId even when two messages are the same campaign sent twice; say so in the run log and the review-task comment so the digest double-count is visible. (2026-09-20 — same campaign sent twice)
D13 [sweep] Write ledger `subject`/`notes` through a CSV writer (quote commas, quotes, newlines). Verify an append by parsing the file (field count equals the header), not by grepping the id. (2026-10-15 — delimiter in value)
D14 [sweep] Dedupe and archive-gate id checks test the id in its own `messageId`/`threadId` column, never anywhere in the line (`notes` can quote other ids); grep only locates a row. Assert the column exists first: `receipts.csv` uses `source`; `newsletters.csv` and `promotions.csv` use `from_address`. A 0 for a sender with history is a broken check. (2026-10-05; 2026-10-23)
D15 [sweep] A ledger repair is a write: make the minimal one-line edit, then `git diff --numstat` must show exactly the intended inserts/deletes (a pure append is N/0). Ledgers mix CRLF and LF; never rewrite a whole file. (2026-10-15)
D16 [sweep] If the `get_thread` read-back refuses after a write ("The caller does not have permission"), run `search_threads in:anywhere` with `includeTrash: true` before calling the write unverified. If Eriks trashed it mid-sequence: the label-delta check is void for that label, the archive is not owed, but the ledger row is still written. (2026-09-27 — trashed between label and read-back)
D17 [sweep] Gmail "Resource has been exhausted": do not retry out of it. Probe `list_labels` and `search_threads` with `view: THREAD_VIEW_IDS_ONLY`; if both answer, record a partial sweep ("skip test completed for N of M"), label nothing unverified, advance no watermark, and never reuse the previous slot's census as present state. (2026-10-28 — Gmail cost quota blocked the sweep)
D18 [sweep] Report quota yield as "this run got N of M", never as a property of a call shape. A new thread whose body cannot be read is left unlabelled, not guessed. (2026-10-28 — cheap shape got 1 of 60)
D19 [sweep] On the second consecutive quota-blocked sweep, open one `[Needs Eriks]` task (cause unknown, stated default keep the cadence); later blocks comment on that task instead of opening more. (2026-10-28 — second consecutive quota block)
D20 [sweep] A timed-out Gmail write is indeterminate: do not retry until `list_labels` counts (`INBOX`, the target label) show whether it landed. Counts prove "not landed" but cannot tell two identical writes from one. (2026-10-28 — timed-out write)
D21 [sweep] Todoist tools absent from the session after one `ToolSearch select:` retry is a tracker outage: `ListConnectors` "connected" is not the `user-info` control. Write nothing to the tracker, advance nothing, and log the cost (Step 0 §4 skipped: defaults in force by omission). (2026-09-27 — connector publishes no tools)
D22 [sweep] A Todoist HTTP 503 is recorded at Step 0, but re-test `user-info` once at the first later step that needs the tracker; do not carry the Step 0 verdict to close-out. (2026-10-22 — sustained 503)
D23 [sweep] Looking up the day's review task: `find-tasks` omits completed tasks, so empty means "no open task", not "no task". Also check `find-completed-tasks` for the day, or `fetch-object` on the id quoted in the previous run-log entry, before creating. (2026-09-25 — completed review task invisible)
D24 [sweep] Before claiming a `[Needs Eriks]` task is open, or completing it, `fetch-object` it and read `checked`/`completedAt`. With a burst of answers, test each against the evidence on its own. (2026-09-30 — seven answers at once)
D25 [sweep] Every `add-tasks` payload states `projectId`, `sectionId`, `priority` and `dueString` explicitly, built from `state/state.json` ids before composing the description. An omitted `projectId` lands the task in Todoist's Inbox with `successCount: 1`; read back `projectId` and `sectionId`, not only contents. (2026-10-09 — add-tasks omits projectId; 2026-10-29 — recurred)
D26 [sweep] If a task lands outside Personal, report it, create the correct task, name the stray in that task's first description paragraph, and never use a forbidden tool (`delete-object`, `project-move`) to tidy it. (2026-10-09; 2026-10-29)
D27 [sweep] The number of labels `list_labels` returns oscillates between calls and is not a containing total. Pair the sweep count with `INBOX.threadsTotal` and per-label `threadsTotal`; do not read a change in label count as a created or deleted label. (2026-10-02 — label total oscillates)
D28 [sweep] If the sweep's thread count exceeds `INBOX.threadsTotal`, say the impossibility test failed and the cause is unknown; do not pick whichever total closes the arithmetic, and do not advance the watermark past the newest message actually read. (2026-10-28 — search_threads can lead list_labels)
D29 [sweep] A census has two invariants: contained count at most its container, and parts summing to the whole at every level (per-label in-inbox counts sum to the already-labelled count). (2026-10-11 — per-label figure never summed)
D30 [sweep] Investigate a census that does not reconcile with a read before reporting, favourable gaps included; never blame "the user probably did something" without proof. A trashed thread leaves a user label's `threadsTotal` and `UNREAD`. (2026-09-14; 2026-09-30)
D31 [sweep] `UNREAD` excludes `TRASH`: a Trash entry or 30-day purge moves `TRASH` only, and an `UNREAD` drop is not a read event when a trash happened in the same window. (2026-10-26 — entering Trash; 2026-10-28 — purge with UNREAD flat)
D32 [sweep] A census term no read can locate is recorded as "unexplained", naming the thread or label it would live in, and handed forward as a standing item. Bracket the query (same operator at 2-3 thresholds) so a populated sibling controls an empty answer. A defect on one operator (`in:spam`) never licenses declining another (`in:trash`). (2026-10-13 ×2; 2026-10-24)
D33 [sweep] Before recording a term as "unexplained" and handing it forward, re-add the list it came from and re-read, by line number, any sibling-run entry the discrepancy is stated against. (2026-10-24 — phantom hypothesis)

## [all] — any external write or log claim

D34 [all] Every number, id, date or count that appears in an external write (Todoist comment, task description, ledger row, brief) is a claim: produce it with a command run this run, or cut it. The decorative sentence is the riskiest one. (2026-10-03; 2026-10-04)
D35 [all] Verify units as well as value: print the ordinal in the units the sentence claims; never copy a script's display index (`enumerate(...)+2`) into prose. (2026-10-08; 2026-10-28 — self-correction rule)
D36 [all] A figure taken from another run's entry or from a task description (inbox size, counts) is re-derived from this run's own tool results or not written. Compute every count in a counts comment before the task-lookup step, and re-derive any number appearing after it. (2026-10-28 — unfinished self-correction; prior-run-figure trap)
D37 [all] A clause characterising another run ("first run to...", "earlier runs labelled N", "new since the last run") requires reading `logs/run-log.md` first; otherwise cut it. A claim that something is "a finding", "new" or "first seen" needs a grep of the log and governing file first. (2026-10-11; 2026-10-15; 2026-10-19 — novelty)
D38 [all] A statement of a thread's live state ("still in the inbox", "has left") is resolved against this run's own `in:inbox` id list, then `in:anywhere` + `includeTrash` if absent. A task's description or comments are never evidence of present state. (2026-10-19 — claim about a thread's state)
D39 [all] Never write an identifier for an object this run has not yet created (comment id, task id, ordinal): create the referenced object first and copy its id from the response. Cite another comment, task or row by id, with any date read off the object's own field, never recalled. (2026-10-28 ×2 — forecast id; cross-reference by date)
D40 [all] Do not put "X... wait, actually Y" in a write; finish the self-correction in the draft and delete the X. (2026-10-28 ×2)
D41 [all] Produce a bucket size by listing its ids and counting the list, before composing the sentence. Report both halves of a two-bucket split with ids; a sum check passes on swapped buckets. (2026-10-14, 10-22, 10-24, 10-27 — two-bucket miscounts)
D42 [all] Say whether a figure describes the run at open or at close when a bucket changes mid-run. Two counts over one list (threads vs the tasks holding them) and page sizes each get their own count of the list. (2026-10-24; 2026-10-27 ×3)
D43 [all] When a sum does not reconcile, never patch the breakdown in prose. Write every bucket's members out, re-derive every class size from that list, and disclose the repair with the superseded text quoted. (2026-10-28 — ninth miscount)
D44 [all] Never read `logs/run-log.md` with `grep -A/-B` or a line window; address an entry by line (`sed -n 'Np'`), noting entries can span lines. Parse headings as `^- (\*\*)?YYYY-MM-DD` (some are bolded). Print compared lines untruncated. (2026-10-14; 2026-10-16)
D45 [all] `grep -c` on the run log counts entries that mention a phrase, not runs that met the condition. Count a string only a run in that condition emits, or say "entries mentioning X". (2026-10-28 — repeat-counter)
D46 [all] Never test an exit status through a pipe (`cmd | tail; then ...`); test the command directly or use `${PIPESTATUS[0]}`. Pair every git mutation with `git rev-parse HEAD` in the same command and believe the state read over a printed status line. (2026-10-03 ×2; 2026-10-05)

(2026-09-21 — replacement order)
